# 0032 — Передавати файл імпорту Prom тілом запиту

- **Status:** Accepted
- **Date:** 2026-10-10
- **Deciders:** Serhii (Architect / Tech Lead)
- **Supersedes:** [ADR 0031](0031-hand-the-import-file-to-prom-from-the-public-bucket.md)

## Context

[ADR 0031](0031-hand-the-import-file-to-prom-from-the-public-bucket.md) обрав імпорт за посиланням
(`import_url`) з файлом у публічному бакеті R2. Імпорт файлом (`import_file`, multipart) він відкинув
з однієї причини: той вимагав би ще однієї проби на живому магазині. Контрольна відправка 2026-10-10
цю причину зняла і знайшла в `import_url` побічний ефект:

- `import_file` перевірено двічі. На пробі він створив товар, у контрольній відправці дочитав фото
  повтором. `mark_missing_product_as: none` і `not_in_file = 0` поводяться так само, як в `import_url`.
- `import_url`, поданий через API, зберігає посилання в кабінеті «Імпорт товарів». Автооновлення там
  стоїть «Ніколи», тож Prom сам файл не перечитує. Але кожна відправка перезаписує посилання, і
  ручний «Почати імпорт» у кабінеті після відправки впаде на вже видаленому файлі.

## Decision drivers

- §1 QG-1: гарантія недоторканності каталогу перевірена на обох способах подачі.
- PRD §6.1: назовні йдуть лише дані картки й публічні адреси фото.
- `ARCHITECTURE.md`: `media` перевіряє справжній тип файлу за сигнатурою. Запис не-зображення без
  перевірки був би першим винятком.
- Кабінет продавця — робоче місце user-а; адмінка не має змінювати в ньому нічого, крім свого товару.

## Considered options

1. **Файл тілом запиту** — `PromAdapter` подає xlsx через `import_file` (multipart) з тими самими
   константами параметрів.
2. **Публічний бакет R2** — рішення ADR 0031 без змін; посилання в кабінеті перезаписується.

## Decision outcome

**Chosen: файл тілом запиту.** Обидва способи тепер перевірені на живому магазині, тож лишається
порівняти ціну. Варіант 2 тримає публічний не-кадр у R2, запис через `media` без перевірки
сигнатури, стрілку `marketplace` → `media`, прибирання файлу на кожному кроці й у свіпі, а ще
змінює налаштування кабінету. Варіант 1 нічого з цього не потребує: файл живе в пам'яті `worker` на
час одного запиту.

## Consequences

**Positive**

- Стрілки `marketplace` → `media` немає; `marketplace` залежить лише від `products`.
- Немає публічного файлу, сиріт у R2 і кроку «прибрати файл»; свіп завислих відправок лише закриває
  рядок.
- Посилання в кабінеті «Імпорт товарів» адмінка не чіпає.

**Negative**

- Повтор для фото (AC-12) не може взяти «той самий файл» зі сховища: `submit` будує його знову з
  картки. Збережена картка між подачами могла змінитися, але повтор з `updated_fields:
  ["images_urls", "presence"]` оновлює лише фото й наявність, тож інші зміни на Prom не потрапляють.
- Розмір тіла запиту обмежує Prom, а не ми; для одного рядка це кілобайти.

**Neutral**

- Prom так само скачує фото сам за публічними адресами R2
  ([ADR 0007](../../product-creation-flow/adr/0007-serve-images-from-a-public-bucket.md)).
- Повернутися до варіанта 2 — замінити один метод `PromAdapter` і повернути залежність від `media`,
  без міграції даних.
