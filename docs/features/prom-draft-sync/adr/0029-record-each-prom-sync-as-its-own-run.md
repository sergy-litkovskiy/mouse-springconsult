# 0029 — Записувати кожну відправку на Prom окремою подією в `product_prom_sync_runs`

- **Status:** Accepted
- **Date:** 2026-10-10
- **Deciders:** Serhii (Architect / Tech Lead)

## Context

Відправка проходить кілька етапів за хвилини й має багато стану: етап, код помилки, ідентифікатор
імпорту Prom, id товару на Prom, лічильник фото K з N, дедлайн очікування. Друга вкладка не має
запустити другу відправку (AC-13), а картка, що вже на Prom, кнопки не показує (AC-14). Форма
зберігання після наповнення живими даними змінюється лише міграцією; її читають і `api`
(картка, стан), і `worker` (етапи).

## Decision drivers

- AC-13: поки відправка триває, друга не запускається — зокрема з іншої вкладки.
- AC-11, AC-12: повтор робить лише те, чого бракує, тож проміжний id товару на Prom треба пам'ятати.
- AC-14: кнопки немає, коли картка вже на Prom — у тому числі в 557 імпортованих з `prom_id`.
- PRD §7: KPI «частка відправок, що з першого натискання дали чернетку з усіма фото» — потрібна
  історія спроб.
- Наявний патерн `product_preparation_runs`: подія без `updated_at`, `started_at` / `finished_at`.

## Considered options

1. **Окрема таблиця відправок** — рядок на кожну відправку чи повтор; правило в БД дозволяє
   щонайбільше один активний рядок на картку; `products.prom_id` пишеться лише на повному успіху.
2. **Колонки в `products`** — 6–8 службових колонок стану відправки прямо в картці.

## Decision outcome

**Chosen: окрема таблиця відправок.** Правило «одна активна відправка» тримає сама база, а не код,
тож дві вкладки не обійдуть його гонкою; історія спроб дає KPI PRD §7; фонова робота не рухає
`updated_at` картки й не зіштовхується зі збереженням форми. `prom_id` лишається єдиною ознакою
«товар уже на Prom» і для 557 імпортованих, і для відправлених кнопкою.

## Consequences

**Positive**

- AC-13 гарантує БД; повторне натискання отримує наявну активну відправку замість помилки.
- Збій посередині не губить проміжний id товару на Prom — повтор продовжує з нього.
- Та сама форма, що й у підготовки: знайомий репозиторій, поллер на фронті, прибиральник завислих.

**Negative**

- Нова таблиця, entity, міграція з робочим `down` і рядок у `ENTITIES` `.dependency-cruiser.cjs`.
- Читання картки має дотягувати останню відправку другим запитом, як уже дотягує галерею.

**Neutral**

- Перехід на колонки пізніше — міграція з перенесенням останнього рядка кожної картки й втрата
  історії.
- Точні колонки, індекси й коди помилок визначає етап 08 (data-model).
