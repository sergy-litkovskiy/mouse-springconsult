# T121 — Розібрати «невірні дані» імпорту Prom і закрити питання токена

## Context

Контрольна відправка 2026-10-10 закрила всі ризики зі строком «до `break-tasks`»
([sad.md §11](../sad.md#11-risks-and-technical-debt)), але лишила три пункти, які вирішує власник,
а не код:

1. **«1 позиція містить невірні дані».** Так кабінет пише у звіті імпорту картки, а API при цьому
   повертає `with_errors_count: 0` і порожні `errors`. Звіт імпорту від 14:45 2026-10-10 ще є в
   історії кабінету. Розгорнути «Докладніше» й записати, яку колонку Prom вважає невірною. Від
   цього залежить набір колонок `buildPromImportFile` ([T129](build-prom-import-file.md)), зокрема
   колонка кількості з типових значень PRD §8: її на пробі не подавали.
2. **Токен.** Перевипустити з одним правом «Продукти та групи: читання та запис» і вирішити, хто
   стежить за строком дії (≤ 1 року). Строк — 2026-10-17 ([PRD §8](../PRD.md#8-open-questions)).
3. **Токен у дев-`.env`.** Для контрольної відправки токен поклали в дев-`.env` під іменем
   `PROM_TOKEN`. За §11 SAD він живе лише в прод-`.env`, а в деві порожній, бо тестової компанії
   Prom немає і будь-яка жива відправка з дев-стенда пише в живий магазин.

## Sequence

[sad.md §6](../sad.md#6-runtime-view), сценарій 1. Пункт 1 стосується файлу, який подає цей крок:

> `worker->>prom: подає імпорт файлом: xlsx з одним рядком, mark_missing_product_as: none`
> `prom-->>worker: остаточний звіт: ненульові лічильники, «не у файлі» = 0`

## Data delta

**Немає, і схема від рішень не залежить.** Рішення пункту 1 змінює лише колонки xlsx, а файл ні
в БД, ні в R2 не зберігається ([ADR 0032](../adr/0032-send-the-import-file-in-the-request-body.md)).
Пункти 2 і 3 зачіпають `process.env`, а не схему.

## API contract excerpt

Коди, від яких залежить, як картка покаже наслідки рішень:

```yaml
    PromSyncErrorCode:
        | `prom_access_denied` | токен недійсний, без права запису чи не заданий (AC-08) | немає | поновити доступ, «Повторити» |
        | `prom_rejected` | Prom остаточно відхилив (`FATAL`) (AC-07) | немає | «Повторити» |
```

## Acceptance criteria

Рішення закриває передумови цих AC, а не пише їх ([PRD §5](../PRD.md#5-acceptance-criteria)):

**AC-01** (US-01) — happy path
**Given** готова картка, якої ще немає на Prom
**When** user натискає «Синхронізувати з Prom»
**Then** на Prom з'являється чернетка без «невірних даних» у звіті імпорту кабінету

**AC-08** (US-03) — доступ
**Given** строк дії доступу минув або доступ не дає права на запис
**When** user натискає «Синхронізувати з Prom»
**Then** картка каже, що доступ треба поновити; хто й коли поновлює — записано

## Checklist

1. Відкрити звіт імпорту 14:45 2026-10-10 у кабінеті, розгорнути «Докладніше» під «1 позиція містить невірні дані», записати поле й текст.
2. Вирішити, яку колонку `buildPromImportFile` змінює чи додає, зокрема чи подає «Кількість» = 1. Записати рішення в рядок §11 SAD «1 позиція містить невірні дані» (закрито, дата, рішення) і в Checklist [T129](build-prom-import-file.md).
3. Перевипустити токен з одним правом; новий — лише в прод-`.env` як `PROM_API_TOKEN`. Записати, хто стежить за строком дії, у PRD §8 (пункт закрито).
4. Прибрати `PROM_TOKEN` з дев-`.env`.

## Out of scope

- Зміна коду файлу імпорту ([T129](build-prom-import-file.md)).
- Будь-яка жива відправка: рішення ухвалюється за наявним звітом у кабінеті.
