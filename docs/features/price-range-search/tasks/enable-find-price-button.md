# T115 — Кнопка «Знайти ціну»: гейт «назва + опис» з чернетки й повідомлення трьох невдач

## Context

Задача повертає user-у кнопку ціни, вимкнену з 2026-09-20 (`priceLookupEnabled = false`,
коментар про T54 у `product-form.html`). До неї ведуть бекенд
([T111](start-price-run-from-draft.md), [T112](search-price-through-gemini.md)) і показ вилки
([T114](show-price-range-and-listings.md)).

Гейт кнопки змінюється: досі вистачало назви, тепер потрібні хоча б одна назва **й** хоча б
один опис з будь-якого майданчика, причому з **чернетки** форми (AC-02). Опис Prom — HTML,
тож «порожній» означає «без тексту після тегів», так само як на сервері.

Текст `price_unavailable` залежить від області: для запуску `price` він не згадує текстів, бо їх
там не було ([ADR 0023](../adr/0023-classify-price-search-failures-and-never-retry-them.md) №6).
За §11 SAD правка `SPEC.md` належить саме story, яка вмикає кнопку ціни.

## Sequence

[sad.md §6](../sad.md#6-runtime-view), сценарії 1, 3 і 4:

> `user->>web: натискає «Знайти ціну» (у чернетці є назва й опис)`
> `web-->>web: тексти на місці, «ліміт пошуку на сьогодні вичерпано» або «пошук ціни не пройшов», кнопка «Знайти ціну» доступна`
> `web-->>user: «вилку не знайдено — повторіть чи уточніть назву», попередня вилка під полем лишається`
> `user->>web: ще клік, поки запуск іде`

## Data delta

**Немає.** Форма пише в картку лише ціну, яку user вписав сам, і робить це звичайним
збереженням. Пропозицію `price` пише `worker` ([data-model.md](../data-model.md), `products.price`).

## API contract excerpt

```yaml
              price:
                $ref: "#/components/examples/PriceRunRequest"

```

## Acceptance criteria

**AC-02** (US-01) — error, [PRD §5](../PRD.md#5-acceptance-criteria)
**Given** у чернетці немає жодної назви або жодного опису
**When** user дивиться на «Знайти ціну»
**Then** кнопка недоступна, а підказка пояснює, що потрібні хоча б одна назва й хоча б один опис з будь-якого майданчика

**AC-07** (US-05) — domain invariant
**Given** у картці вже є вилка або попередній пошук її не знайшов
**When** user знову натискає «Знайти ціну» без змін
**Then** іде новий пошук, нова вилка замінює попередню; поки пошук іде, кнопка вимкнена

**AC-08** (US-06) — відмова зовнішнього сервісу
**Given** user запустив пошук ціни
**When** запуск закрито `price_unavailable`
**Then** user бачить «пошук ціни не пройшов» без згадки текстів, внесене в форму на місці, кнопка доступна для повтору

## Checklist

1. `product-form.ts`: прибрати `priceLookupEnabled` разом із коментарями про T54 у `.ts` і `.html`. Блок `app-suggestion-field` для ціни показується завжди.
2. `canLookUpPrice`: назва Prom чи OLX **і** опис Prom (текст без тегів) чи OLX з чернетки; картка збережена; запуску немає. `rewriteHint` — текст AC-02.
3. Мітка кнопки — «Знайти ціну». Статус під час запуску — «Модель шукає ціну…» (вже є).
4. `run-failure-messages.ts`: текст `price_unavailable` залежить від області запуску. Для `price` — «Пошук ціни не пройшов — спробуйте ще раз.», для `both` — наявний. Каталог, який показує невдалі запуски зі `scope`, бере той самий вибір.
5. Spec форми: кнопка вимкнена без опису, з описом лише з тегів і без назви; увімкнена зі змішаною парою; запит несе чернетку; три коди показують три різні тексти; поле ціни після успіху лишається порожнім.
6. [SPEC.md](../../../../SPEC.md), рядки 12 і 60–61: «пошук ціни відкладено» і `web_search_20260209` → вилка через Gemini з оголошеннями, ціну вписує user (рядок §11 «Розходження: SPEC.md»).
7. Playwright-прохід на живому стеку: запуск з порожнім описом недоступний, вилка з'являється під полем, оголошення відкриваються в новій вкладці, поле ціни лишається порожнім. Gemini для проходу підміняється або кличеться свідомо: free tier, але з квотою 500 на добу.

## Результат

- Поза `/tdd`, окремим комітом: вибір тексту `price_unavailable` за областю запуску живе в
  `runFailureMessage` (`run-failure-messages.ts`), і форма та каталог беруть його звідти. Текст
  `409` `preparation_input_incomplete` тепер називає й опис.
- Playwright 2026-10-09 на живому стеку, картка «Масажна напівсфера AZUNI ASL572». Без обох
  описів, коли опис Prom складається лише з тегів (`<p><br></p>`), кнопка вимкнена з підказкою
  AC-02. Пара «назва Prom + опис OLX» вмикає кнопку. Поки триває пошук, кнопка вимкнена й видно
  «Модель шукає ціну…». Один живий пошук на `gemini-3.5-flash-lite` (≈ $0,008, з дозволу) дав
  «від 955 до 955 ₴» під полем. В модалці одне оголошення OLX з `target="_blank"` і
  `rel="noopener noreferrer"` та дата пошуку. Поле ціни (`234.00`) не змінилось.
- `price_not_found`, `price_quota_exhausted` і `price_unavailable` перевірено через `page.route` на
  старт і полінг: кожен код показує свій текст, а для `price` текст не згадує текстів. Попередня
  вилка й чернетка лишаються, кнопка знову доступна.
