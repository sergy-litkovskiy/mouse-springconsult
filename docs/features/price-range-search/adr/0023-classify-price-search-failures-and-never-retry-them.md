# 0023 — Розрізняти три невдачі пошуку ціни й ніколи не повторювати його автоматично

- **Status:** Accepted
- **Date:** 2026-10-08
- **Deciders:** Serhii (Architect / Tech Lead)

## Context

PRD вимагає трьох різних повідомлень: «пошук не пройшов» (AC-08), «ліміт пошуку на сьогодні
вичерпано» (AC-09), «вилку не знайдено» (AC-10). Сьогодні є лише `price_unavailable`, і він означає
«тексти `both` збережено, ціни немає». pg-boss повторює кожну задачу, що викинула виняток
(`retryLimit: 2`), тож необроблена відмова тихо витратила б три запити з 500 на добу. Коди — це
`errorCode` запуску в `ai.contract.ts`, з яким працюють `worker`, `api` і `web`.

## Decision drivers

- PRD §6: 1 запит до постачальника пошуку на запуск; власного циклу повторів немає, повтор — дія user-а.
- §1 QG-1: тексти, поля й попередня вилка не втрачаються за жодної невдачі.
- §1 QG-2: відповідь моделі без оголошень чи з хибними межами — не вилка (AC-10).
- `CLAUDE.md`: текст для користувача фронт формує за `code`, а не за англійським повідомленням.
- §2: `@google/genai` без `retryOptions` не повторює; добова квота дає HTTP 429 `RESOURCE_EXHAUSTED`.

## Considered options

1. **Три коди, без повтору.** `price_not_found`, `price_quota_exhausted`, `price_unavailable`;
   запуск закривається `failed` без throw.
2. **Один код `price_unavailable` + `errorDetail`.** Причина — у тексті помилки.

## Decision outcome

**Chosen: опція 1.** Опція 2 змусила б `web` розбирати англійський текст помилки, щоб показати
AC-09 і AC-10, всупереч правилу «текст — за `code`».

1. `PreparationService` обгортає виклик `GeminiAdapter` і будь-яку відмову класифікує сам; запуск
   закривається `finishRun(failed)` без throw — pg-boss не повторює, `abandon` не потрібен.
2. **`price_not_found`:** відповідь не розібралась як JSON очікуваної форми, або в ній не 1–5
   оголошень з адресою `http:`/`https:`, або межі не є додатними десятковими рядками з
   `priceFrom ≤ priceTo`. Перевірку робить zod-схема в `GeminiAdapter` (форма) і сервіс (інваріант
   вилки).
3. **`price_quota_exhausted`:** HTTP 429 з ознакою добової квоти в деталях помилки (`quotaId` з
   `PerDay`). Ознаку офіційно не задокументовано; замір перевіряє тіло реальної помилки, а 429 без
   неї стає `price_unavailable`.
4. **`price_unavailable`:** решта — мережа, 5xx, таймаут, недійсний ключ, відмова моделі.
5. У `both` підготовлені тексти зберігаються пропозиціями в усіх трьох випадках (AC-04); пропозиція
   `price` не пишеться, тож попередня вилка лишається.
6. Повідомлення в `web/products/run-failure-messages.ts` — за кодом. Текст `price_unavailable`
   для запуску `price` не згадує текстів: їх там не було.

## Consequences

**Positive**

- Квоту витрачають лише кліки user-а; один клік — один запит до Google.
- User бачить, що робити далі: повторити, уточнити назву чи чекати наступного дня (US-06).

**Negative**

- Контракт `errorCode` розширюється на два значення, і `web` має знати три повідомлення.
- Тимчасовий збій мережі не лікується сам: user натискає кнопку ще раз.
- Розрізнення добової квоти спирається на недокументовану деталь помилки.

**Neutral**

- Помилки поза викликом Gemini (читання кадрів з R2, БД) і далі кидаються й повторюються pg-boss,
  як зараз; запуск закриває `abandon` з `preparation_failed`.
- Наслідок цього: якщо Gemini відповів успішно, а впав запис результату (`finishRun`), задача
  кидає виняток, і повтор pg-boss робить другий запит до Google. «Один запит на запуск» тут не
  тримається; ціна — до 2 запитів квоти, рядок Low у §11 SAD.
