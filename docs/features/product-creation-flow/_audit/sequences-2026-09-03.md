## Skipped — trivial

- **US-07 «Позначити присутність окремо» (AC-13).** Дві незалежні булеві колонки, один хоп
  `web → api → pg`. Інваріант «зняття однієї не змінює другу» тримає форма схеми, а не
  послідовність у часі — діаграма не показала б нічого, чого немає в §5.
- **US-08 «Побачити вартість підготовки» (AC-14).** Читання суми `usage` разом із карткою.
  Дуга збігається з будь-яким читанням картки. Варто повернути в обсяг, якщо етап 08 винесе
  агрегацію в окремий запит або матеріалізує її.

## ADR potential

Скіл ADR не пише — це кандидати для `sdlc:decide-adr` або для етапу 08.

1. **Ключ ідемпотентності задачі підготовки** (сценарій 7). §8 вимагає «задачі ідемпотентні»,
   форми ключа не називає. У діаграмі взято «картка + область + версія входу»: повторний клік
   по незміненій картці не платить двічі, зміна розпізнавання дає новий запуск. Альтернативи
   існують (ключ запиту з фронту, дедуплікація по вікну часу), і вибір видимий у грошах.
2. **Область запуску — «тексти» / «ціна» / «обидва»** (сценарії 7, 8). Прямий наслідок AC-10b,
   але §6 сценарій 5 малює один запуск із двома викликами, тож межа задачі не зафіксована:
   одна задача на запуск чи задача на поле. Впливає на схему таблиці пропозицій (етап 08) і
   на форму ендпоінта (етап 10).
3. **Бюджет повторів і DLQ** (сценарій 7). Кількість спроб, форма наростання паузи і що саме
   бачить `user`, коли задача пішла в DLQ. §9 уже фіксує рішення «власного циклу повторів
   застосунок не має» для сховища — для черги аналогічного рядка немає.
4. **Форма пропозиції ціни** (сценарій 8). Пропозиція несе діапазон із двох чисел, поле
   `price` картки — одне (`decimal(12,2)`, `not null default 0`). Або таблиця пропозицій
   тримає діапазон, або він зводиться до числа у воркері — і тоді AC-08 втрачає предмет.
5. **Автозастосування пропозиції відбувається на читанні картки** (сценарій 9). Обробник
   читання пише в базу. Це буквальне прочитання ADR 0006 («поки збігається — застосовується
   сама»), і власник підтвердив саме його, але альтернатива — застосовувати у воркері одразу
   після запису пропозиції — лишає `GET` чистим при тому самому правилі.
