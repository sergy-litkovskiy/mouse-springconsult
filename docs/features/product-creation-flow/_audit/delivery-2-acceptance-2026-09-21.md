# Delivery 2 acceptance run — product-creation-flow

- **Date:** 2026-09-21
- **Task:** [T33](../tasks/verify-delivery-2.md)
- **Commit under test:** `b257437` (`main`)
- **Stand:** локальний Docker Compose (colima): `api` на `:3100`, `web` на `:4200`, `worker`,
  PostgreSQL 18, **справжній** бакет R2 і **справжній** ключ Anthropic (лише у фазі 2). Caddy в
  прогоні не брав участі: межі тіла запиту поставка 2 не змінювала, їх закрито в T23.
- **Tools:** `curl` з cookie-jar (через Python), `playwright-cli` для UI, `psql` для інваріантів,
  логи `worker` для черги. Автоматизованого e2e-набору немає, і цей прогін його не заводить.
- **Недосяжна модель без правки коду.** Штатний `worker` зупинено, замість нього працювала копія
  `docker compose run --name mouse-t33-deadai worker …` зі зміненим `ANTHROPIC_BASE_URL` (SDK читає
  його з середовища):
  - `http://127.0.0.1:9` для QG-1. `fetch` відхиляє порт ще до з'єднання, SDK бачить
    `APIConnectionError: Connection error.` і сам повторює двічі, тож одна спроба триває ~2 с;
  - `http://api:3000` для черги й ліміту. Власний `api` миттєво відповідає 404, SDK такого не
    повторює, і спроба займає мілісекунди, а не 2 с. Так спроби не впливають на замір черги.

  Перед поверненням штатного `worker` у `pgboss.job` не лишилось жодної задачі в станах
  `created`/`retry`/`active`, а всі 43 запуски `T33-` мали `failed`: живий воркер не отримав
  жодного платного повтору.
- **Start / end state:** `products` 557 / `product_images` 4392 / `product_preparation_runs` 0 /
  `product_field_suggestions` 0 до прогону й після нього. `md5` обох таблиць карток і кадрів після
  прибирання збігся з тим, що був до прогону. Картка-джерело кадру («Ділова сукня, колір беж…»)
  читається байт у байт як до прогону. Шість тестових карток `T33-` видалено через
  `DELETE /products/:id` (6 × 204), шість публічних адрес їхніх кадрів відповідають 404.
- **API spend:** 3 виклики `claude-sonnet-5`, 7688 вхідних і 1227 вихідних токенів. За цінами
  $2 / $10 за мільйон це $0,0154 + $0,0123 = **$0,028** при погодженій стелі $0,30.

### Спостереження (не дефекти)

- **Черга під сплеском.** Воркер бере по одній задачі й після кожної чекає інтервал полінгу,
  тож виходить близько однієї спроби на секунду. pg-boss віддає задачі за `createdOn`, і повтори
  ранніх запусків (через 10 і 20 с) стали перед q19 і q20. Реальне навантаження — 50–100 карток
  на місяць і один-два адміни, тож на ньому черга вільна (пункт 4, p95 883 ms). Слід пам'ятати й
  інше: справжній виклик триває 14 с, тож другий запуск, поставлений під час першого, чекатиме
  саме стільки. Рядок PRD §6 умов навантаження не називає.
- **Очікування «модель не пише в `products`» у плані прогону було неточним.** Воркер справді
  пише лише пропозиції. Недоторкані поля заповнює `api`, коли читає картку, і це задумана
  поведінка ([sad.md §6](../sad.md#6-runtime-view), сценарій 9).
- **«Предмет з особистої колекції».** Після виклику 1 обидва згенеровані описи не містять
  фраз про особисту колекцію чи запаси (`~* 'особист|колекц|запас'` → false).

  2026-09-21 поставку 2 ще не задеплоєно.
