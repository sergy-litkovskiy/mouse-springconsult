# T102 — Фільтри каталогу застосовуються самі, без кнопки «Застосувати»

## Context

Запит 2026-10-07. «Назва» й «Опис» уже фільтрують наживо: від трьох символів, з debounce
300 мс ([T63](search-titles-live-from-three-chars.md), AC-57, цикл `valueChanges` у
конструкторі `product-catalog.ts`). Решта панелі чекає на кнопку «Застосувати». Власник просить,
щоб кожен фільтр застосовувався сам, а кнопку прибрати.

**Що змінюється — лише `web`.**

- **Селекти** «Опубл. на Prom», «Опубл. на OLX» і «Картка готова» застосовуються одразу на
  `valueChanges`, без debounce: вибір у селекті — завершена дія, чекати нічого.
- **Категорія.** `pickCategory` і `removeCategory` одразу виконують navigate з усім списком
  chips. Порожній список дає `category: null`: `category=` з порожнім значенням `api` відхиляє
  з `400` (AC-56).
- **«Ціна від» / «Ціна до»:**
  - debounce 300 мс;
  - значення застосовується, якщо після `normalizePrice` відповідає `pricePattern` і ціла
    частина має щонайменше дві цифри (стала `priceFilterMinDigits = 2` у
    `product-catalog-query.ts`): на першій цифрі «1000» фільтр ще не має сенсу;
  - порожнє поле знімає фільтр;
  - одна цифра або невалідне значення нічого не змінюють; помилка поля — як зараз;
  - пара min > max не застосовується, повідомлення `priceRangeInvalid` лишається.

  Правило двох цифр діє лише у формі: `api` і збережена адреса `?priceMin=5` працюють як раніше.
- **Спільне для всіх полів:**
  - кожне застосування скидає `page`;
  - значення, що дорівнює вже застосованому, пропускається. Це той самий захист від «луни»
    `effect` URL → форма, що вже стоїть у T63: без нього Back і F5 давали б зайві навігації й
    губили б сторінку.
- **Кнопку «Застосувати» прибрати** разом з `(ngSubmit)` форми. «Скинути» лишається і робить
  **одну** навігацію, яка знімає всі фільтри й сортування ([T101](sort-catalog-newest-first.md)).
  `filters.reset()` породжує `valueChanges` кожного селекта, і без захисту вище «Скинути» дав би
  кілька навігацій замість однієї.

**Тести.** Тести з хелпером `submitFilters()` (`product-catalog.spec.ts`, 11 викликів) RED
переписує на живу поведінку з фейковим часом, а не видаляє: їхні перевірки адреси й запиту
лишаються предметом.

## Sequence

Власного сценарію немає: живе застосування — частіший виклик того самого `listProducts`. Так
само [sad.md §6](../sad.md#6-runtime-view) описує стан форми:

> «власного сценарію це не має, бо це стан форми на фронті, а не запит до `api`»

## Data delta

**Немає.** Ні схеми бази, ні контракту `api` зміна не чіпає.

## API contract excerpt

```yaml
        - { $ref: "#/components/parameters/Sort" }
        - { $ref: "#/components/parameters/Direction" }
```

Параметри `listProducts` лишаються без змін: форма лише частіше шле той самий запит.

## Acceptance criteria

AC-93 нове; до [PRD §5](../PRD.md#5-acceptance-criteria) його вносить крок 7 чекліста разом із
правками AC-29, AC-56 і AC-57.

**AC-93 (US-07) — happy path**
**Given** `user` відкрив `/products` без фільтрів
**When** він обирає «Картка готова: Так» і не тисне жодної кнопки
**Then** адреса отримує `ready=true`, запит до `api` іде з тим самим параметром, а пагінатор повертається на першу сторінку

**AC-93 — edge case (ціна)**
**Given** поле «Ціна від» порожнє
**When** `user` вводить `1`, потім `10`, потім дописує до `1000`
**Then** на `1` запиту немає, на `10` запит з `priceMin=10` іде приблизно через 300 мс, а набір `1000` поспіль дає один запит з `priceMin=1000`; збережена адреса `/products?priceMin=5` фільтрує як раніше

**AC-93 — edge case (скидання)**
**Given** застосовано «Картка готова: Так», категорію «Миші» й сортування за ціною
**When** `user` тисне «Скинути»
**Then** адреса змінюється один раз: у ній немає ні фільтрів, ні `sort`, ні `direction`

**AC-93 — error**
**Given** у «Ціна від» застосовано `500`
**When** `user` вводить у «Ціна до» `100`
**Then** нового запиту немає, повідомлення про хибний діапазон видно, а в адресі лишається лише `priceMin=500`

## Checklist

1. `product-catalog.spec.ts`: селекти й категорія — застосовуються без кнопки, порожній список chips дає запит без `category`; тести з `submitFilters()` переписати на живу поведінку.
2. `product-catalog.spec.ts`: ціна з фейковим часом — `1` без запиту, `10` із запитом після 300 мс, набір `1000` дає один запит, порожнє поле знімає фільтр, min > max без запиту.
3. `product-catalog.spec.ts`: «Скинути» дає одну навігацію; Back після фільтра не дає зайвої.
4. `product-catalog-query.ts`: стала `priceFilterMinDigits` і функція «ціна достатня для фільтра»; тест у `product-catalog-query.spec.ts`.
5. `product-catalog.ts`: підписки селектів і ціни з `takeUntilDestroyed`, navigate у `pickCategory`/`removeCategory`, `applyFilters` прибрати; `resetFilters` — одна навігація.
6. `product-catalog.html`: прибрати кнопку «Застосувати» й `(ngSubmit)`.
7. `PRD.md §5`: AC-93; UI-частина AC-29 («натискає «Застосувати»»), AC-56 happy path і edge «скидання фільтра», формулювання AC-57 — без кнопки.
8. `pw`: кожен селект і chip застосовуються одразу; ціна `1`/`10`/`1000` — за запитами в network; Back; кнопки «Застосувати» немає.
