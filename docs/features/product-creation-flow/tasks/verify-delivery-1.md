# T23 — Приймання поставки 1

## Context

Остання задача поставки 1 і єдина в ній, яка не пише коду фічі. Стека метрик і алертів у
системі немає й фіча його не вводить ([sad.md §7](../sad.md#7-deployment-view)) — тож
перевірка якостей є ручним прогоном, і його треба виконати один раз свідомо, а не
сподіватись, що це станеться саме собою на першій картці.

## Sequence

Задача **прогонить усі чотири сценарії поставки 1**, а не реалізує один:
[sad.md §6](../sad.md#6-runtime-view) — сценарій 1 (додавання кадру), 2 (сховище
недоступне), 3 (головний кадр), 4 (видалення). Ключовий для приймання — **сценарій 2**, бо
він єдиний не перевіряється щоденною роботою:

> `r2--xapi: клієнт S3 повторює перехідні збої і здається`
> `Note over api,pg: рядок не створюється — неузгодженого стану не виникає`

## Data delta

**Задача не змінює схему — вона її перевіряє.** Предмет:

| Що перевіряється | Очікуване |
|---|---|
| міграція [T12](drop-product-image-url.md) вниз і вгору | проходить на **копії бази з даними**, не на порожній |
| `product_images` після відмови сховища | **рядка не додалось** |
| `product_images` після видалення картки | рядків не лишилось (каскад) |
| `product_images_main_key` | рівно один головний кадр після серії перепризначень |

## API contract excerpt

Прогін звіряє відповіді з контрактом, зокрема коди, яких щоденна робота не дає:

```yaml
        "409":
          description: Галерея вже має десять кадрів (AC-02)
        "413":
          description: Файл більший за 10 МБ (PRD §6)
        "422":
          description: Вміст файлу не є зображенням (ADR 0004)
        "502": { $ref: "#/components/responses/StorageUnavailable" }
```

## Acceptance criteria

**QG-1** ([sad.md §10](../sad.md#10-quality-requirements))
**Given** сховище не відповідає під час завантаження кадру або під час видалення
**When** `user` виконує дію
**Then** усе вже збережене лишається цілим, помилка доходить доменним кодом, картка придатна для повтору

**QG-2** ([sad.md §10](../sad.md#10-quality-requirements))
**Given** `user` обирає файл у діалозі галереї
**When** запит ще не повернувся
**Then** превʼю вже намальоване, і форма лишається придатною до редагування

## Checklist

1. **QG-1.** Підмінити креденшели й домен R2 на недосяжні; спробувати додати кадр і видалити картку. Перевірити: рядка не додалось, у відповіді доменний код, решта картки читається.
2. **QG-2.** На дроселі мережі перевірити, що превʼю зʼявляється до відповіді і форма не блокується.
3. **Межі вводу.** Одинадцятий кадр відхиляється; файл 10 МБ проходить, 11 МБ — кодом, а не обривом. Обидва боки пари лімітів: через `api` напряму й через `caddy`.
4. **Міграція.** `db:migrate` вниз і вгору на копії бази **з даними**.
5. **Наскрізний прохід AC** поставки 1: AC-01, AC-02, AC-03, AC-04, AC-07, AC-09, AC-12, AC-13, AC-15 плюс AC-16, AC-17, AC-18 з [T01](align-prd-with-architecture.md).
6. **Каталог, p95 ≤ 500 ms** — двадцять карток, 20 повторів, тривалість запиту з pino-логів.
