# T55 — Форма показує тексти, які api застосував сам

## Context

Дефект з [приймання поставки 2](../_audit/delivery-2-acceptance-2026-09-21.md) (T33, AC-05).
Сценарій: у новій картці є кадр і порожні описи, адмін тисне «Згенерувати все». Запуск
завершується, і `api` під час читання картки сам переносить пропозиції в недоторкані поля. Відповідь
`GET` приходить із заповненими `descriptionProm`, `descriptionOlx` і `seoKeywords` та порожнім
`pendingSuggestions`. Форма ж у `reread()` оновлює лише `card`, а поля не чіпає, тож на екрані
не з'являється нічого: ні значень, ні пропозицій праворуч. Далі «Зберегти» надсилає
`descriptionProm: ""` і `seoKeywords: []` і стирає щойно згенеровані тексти. На прогоні це
запити #113 і #114.

Це розбіжність з архітектурою: [sad.md §6](../sad.md#6-runtime-view), сценарій 9, прямо
обіцяє, що user побачить оновлений опис Prom без підтвердження. Порожня картка — найчастіший
випадок, тож без виправлення основний сценарій поставки 2 губить результат.

## Sequence

> `web->>api: перечитує картку`
> `api-->>web: значення полів, а поруч — непідтверджені пропозиції`
> `web-->>user: опис Prom оновлено сам, опис OLX лишився вашим із пропозицією поруч`

Третій крок форма зараз пропускає: значення, які `api` застосував, до полів не доходять.

## Data delta

**Немає.** Ні схема, ні контракт, ні `api` не змінюються: сервер уже віддає правильну картку.

## API contract excerpt

```yaml
            pendingSuggestions:
              type: array
              description: >-
                Непідтверджені пропозиції поруч зі значеннями (sad.md сценарій 9) —
                те, що звірка цього ж читання лишила людині (AC-11). `resolution`
                і `resolvedAt` тут завжди `null`.
```

## Acceptance criteria

**AC-05** ([PRD §5](../PRD.md#5-acceptance-criteria)) — happy path
**Given** картка з кадром і порожніми описами, форма відкрита
**When** запуск текстів завершився, і `api` застосував пропозиції до недоторканих полів
**Then** поля «Опис для Prom», «Опис для OLX» і «Ключові слова» показують ці значення без
жодного кліку, а «Зберегти» надсилає саме їх

**AC-11** — domain invariant
**Given** поки запуск ішов, адмін змінив у формі «Опис для OLX»
**When** запуск завершився, і форма перечитала картку
**Then** у полі лишився введений текст, а поля, яких адмін не торкався, отримали значення з
відповіді

## Checklist

1. `product-form.ts`, `reread()`: після `GET` для кожного поля з `RewritableField` взяти з
   відповіді значення, якщо воно відрізняється від картки, з якою форма працювала до запуску, а
   контрол досі тримає старе значення тієї картки. Поле, змінене під час запуску, лишається як є
   (AC-11). Перетворення значень — як у `fill()`: ключові слова через кому.
2. `product-form.spec.ts`: тест «порожня картка → `succeeded` → перечитування з заповненими
   полями й `pendingSuggestions: []` → поля показують значення, `PATCH` після «Зберегти» несе їх».
   Другий тест — поле, змінене під час запуску, лишається зміненим. Наявний тест AC-11
   лишається зеленим.
3. `pw` на живому стеку: нова картка з кадром, «Згенерувати все», поля заповнились без кліку,
   «Зберегти», у базі згенеровані значення. Це один платний виклик, ≈ $0,012 за заміром T33.

  `api`, до форми не дійде, і «Зберегти» його перезапише. Випадок рідкісний. Його не покрито
  тестом і не виправлено.
