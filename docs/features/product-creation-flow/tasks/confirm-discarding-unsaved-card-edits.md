# T83 — Картка не закривається мовчки, коли в полях є незбережені правки

## Context

Знахідка UX-аудиту 2026-10-02 (Playwright MCP, живий стек). Людина змінила «Назву для OLX» і
натиснула Esc або клацнула повз діалог. Картка закрилася без запитання, а після повторного
відкриття правки не було. Один випадковий клік повз діалог коштує всіх правок картки. Так само
поводиться кнопка «Скасувати»: у шаблоні це `[mat-dialog-close]="changed()"`.

**Що вважати незбереженою правкою.** Значення полів форми розходиться з карткою, яку форма
прочитала останньою (`card()`): обидві назви, обидва описи, ключові слова, ціна (порожнє поле
означає `"0.00"`, див. `priceFieldValue`), категорія, стан і обидві відмітки. Прапорець `dirty`
не годиться: сітка chips повертає список ключових слів формі на кожному blur, тож поле стає
`dirty`, навіть якщо його просто пройшли. Так само порівнює `reread()`. Кадри галереї сервер
зберігає одразу, тож правками вони не є. Пропозиція, скопійована в поле стрілкою «<- AI», з
[T90](copy-suggestion-into-form-field.md) — правка, як і будь-яке введення
([ADR 0017](../adr/0017-keep-one-latest-suggestion-per-field.md)).

**Що робимо.** `ProductForm` вмикає `dialogRef.disableClose`. Натиснутий Esc
(`keydownEvents`), клік по підкладці (`backdropClick`) і кнопка «Скасувати» йдуть в один
метод `close()`. Якщо незбережених правок немає, він закриває діалог з `changed()`, як і зараз.
Якщо є, `close()` відкриває наявний `ConfirmDialog` із заголовком «Закрити без збереження?»,
текстом «Правки в полях картки буде втрачено.» і кнопкою «Закрити без збереження». «Скасувати»
в цьому запитанні повертає до картки з правками. Після «Зберегти» діалог закривається так само,
як і зараз.

## Sequence

Запитів це не змінює: «Зберегти» йде тим самим шляхом сценарію 6
[sad.md §6](../sad.md#6-runtime-view), а закриття без збереження нічого не надсилає.

> `web->>api: зберігає картку`

## Data delta

**Немає.** Правка лише у `product-form.ts` і `product-form.html`.

## API contract excerpt

Без правок поля картка нічого не надсилає. Що могло б загубитися — тіло цього запиту:

```yaml
      operationId: updateProduct
            schema: { $ref: "#/components/schemas/ProductUpdateRequest" }
    ProductUpdateRequest:
      description: Усі поля опційні — PATCH змінює лише надіслане.
```

## Acceptance criteria

Нове AC із UX-аудиту 2026-10-02; до [PRD §5](../PRD.md#5-acceptance-criteria) його вносить
крок 5 чекліста.

**AC-76 (нове) — happy path**
**Given** `user` змінив у відкритій картці будь-яке поле й не зберіг
**When** тисне Esc, клацає повз діалог або тисне «Скасувати»
**Then** картка лишається відкритою з правками, а система питає «Закрити без збереження?»; лише підтвердження закриває картку без запиту `PATCH`

**AC-76 — edge case**
**Given** `user` відкрив картку й лише пройшов поля (зокрема ключові слова) або додав чи видалив кадр
**When** тисне Esc, клацає повз діалог або тисне «Скасувати»
**Then** картка закривається одразу, без запитання, а каталог перечитується, якщо змінювались кадри

## Checklist

1. `product-form.spec.ts`: тести на AC-76 — правка поля й три способи закрити (Esc, підкладка, «Скасувати») відкривають `ConfirmDialog`; відмова лишає форму, згода закриває без `update`; пройдене поле ключових слів і зміна кадру закривають одразу.
2. `product-form.ts`: похідний `hasUnsavedEdits` — порівняння значень форми з `card()`, без `dirty`; ціну порівнювати через `priceFieldValue`.
3. `product-form.ts`: `dialogRef.disableClose = true`; `close()` для `keydownEvents` (Escape), `backdropClick` і кнопки; запитання — наявний `ConfirmDialog`.
4. `product-form.html`: «Скасувати» викликає `close()` замість `[mat-dialog-close]`.
5. `PRD.md §5`: AC-76 з посиланням на цю story.
6. `pw` на живому стеку: правка назви, тоді Esc, клік повз діалог і «Скасувати»; без правки — закриття без запитання. Нічого не зберігати.
