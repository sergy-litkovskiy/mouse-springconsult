# T33 — Приймання поставки 2

## Context

Дзеркало [T23](verify-delivery-1.md) для другої поставки. Спосіб перевірки взято дослівно з
[sad.md §10](../sad.md#10-quality-requirements): «той самий прогін із недосяжним Anthropic —
тексти лишаються пропозиціями, ціну можна запросити окремо».

Разом з релізом поставки 2 запускається відлік «30 днів» для трьох KPI
[PRD §7](../PRD.md#7-metrics--kpis), перебазованих задачею [T01](align-prd-with-architecture.md).

## Sequence

Прогін проходить **усі пʼять сценаріїв поставки 2** ([sad.md §6](../sad.md#6-runtime-view)):
5 (часткова відмова), 7 (тексти), 8 (ціна), 9 (повторний запуск не перезаписує правку).
Головний для приймання — **сценарій 5**:

> `worker->>pg: пише пропозиції текстів і usage виклику`
> `anthropic--xworker: сервіс відповів помилкою`
> `worker->>pg: позначає цінову частину невиконаною`

## Data delta

**Задача схему не змінює — вона її перевіряє:**

| Що перевіряється | Очікуване |
|---|---|
| `product_field_suggestions` після відмови цінового виклику | рядки текстів **на місці**, рядка ціни немає |
| `products` після будь-якого запуску | жодного рядка, написаного моделлю |
| `product_preparation_runs_idempotency_key_key` | повторний запуск того самого входу не створює другого рядка |
| сума `input_tokens` / `output_tokens` | збігається з показаною вартістю картки |

## Acceptance criteria

**QG-1** ([sad.md §10](../sad.md#10-quality-requirements))
**Given** модель недоступна або повернула помилку
**When** `user` запустив підготовку
**Then** галерея й усе внесене ціле, помилка видима, картка придатна для повторного запуску

**QG-3** ([sad.md §10](../sad.md#10-quality-requirements))
**Given** `user` виправив опис під OLX вручну
**When** підготовка запускається ще раз
**Then** поле не змінилось, пропозиція чекає поруч

## Checklist

1. **QG-1 з недосяжною моделлю.** Підмінити ключ або домен Anthropic; запустити підготовку. Перевірити AC-10.
2. **AC-10b.** Змусити відмовити саму цінову частину; тексти лишаються пропозиціями, `scope: price` запускається окремо.
3. **QG-3 / AC-11.** Виправити опис під OLX руками, запустити ще раз: поле не змінилось.
4. **Черга.** `enqueue → started` ≤ 5 с, 20 повторів, з логів воркера.
5. **AC-14.** Вартість картки після кількох запусків звірена запитом до бази.
6. **Ліміт частоти.** Вичерпати вікно; відмова видима й названа.

## Out of scope

- Стеля вартості картки в грошах: відлік для неї починається тут, але число ставиться **після першого місяця роботи**.
- Питання «предмет з особистої колекції» — має бути вирішене **до релізу**: саме ця поставка формує текст під OLX. Задача його не закриває, а **блокується** ним.
