# T32 — Фронт підготовки: запуск, полінг, пропозиції, вартість

## Context

Екран, на якому обіцянка [PRD §2](../PRD.md#2-goals) стає видимою: тексти під обидва
майданчики й ціна зʼявляються в картці одним запуском, без переходу в зовнішній чат.

Полінг зʼявляється саме тут — і це адитивна зміна, яку
[sad.md §9](../sad.md#9-architecture-decisions) свідомо лишив без ADR: у поставці 1 його не
було, бо фонової роботи не було.

**Уточнення 2026-09-12 (мокап картки, `docs/assets/add-edit-product-feature.pdf`).** Замість
окремої «панелі підготовки» з вибором області — парне поле на кожен текстовий рядок
(заголовок Prom/OLX, опис Prom/OLX, ключові слова): ліворуч поточне значення (ручний ввід
або застосована пропозиція), праворуч — остання пропозиція моделі, і дві кнопки:

- **«Generate all»** (одна кнопка нагорі, над галереєю) — запускає `scope: texts`,
  розпізнає товар із головного кадру й заповнює праворуч усі поля одразу ([ADR 0014](../adr/0014-let-ai-recognize-the-item-from-photos.md)).
- **«? -> AI»** (біля кожного поля) — запускає `scope: field` для цього поля з поточної
  чернетки ліворуч, без фото (US-10, [ADR 0015](../adr/0015-add-per-field-text-rewrite-scope.md)); недоступна, доки поле порожнє (AC-22).
- **«<- AI»** (біля кожного поля) — приймає останню пропозицію цього поля
  (`acceptFieldSuggestion`, [T30](add-suggestion-resolution-endpoints.md)) і копіює її
  значення в поле ліворуч. На щойно створеній картці перша пропозиція для поля вже
  застосована сама (ADR 0006) — кнопка стає потрібною саме в момент розходження (AC-11).

Ціна лишається окремою дією поза цим паттерном — `scope: price` не читає чернетку, кличе
`web_search`.

## Sequence

[sad.md §6](../sad.md#6-runtime-view), **сценарій 7** — цикл опитування, **сценарій 10** —
регенерація й прийняття одного поля, і **сценарій 5** — часткова відмова, яку фронт має
показати:

> `web->>api: перечитує картку`
> `api-->>web: тексти є пропозиціями, ціни немає`
> `user->>web: запитує саму лише ціну, не перезапускаючи тексти`

## Data delta

**Немає.** Але одна властивість схеми визначає поведінку таймера: `created_at` запуску є
входом обмеження частоти ([data-model.md](../data-model.md)), тож полінг, який не зупинився
після виходу з екрана, зʼїдає ліміт і коштує грошей.

## Acceptance criteria

**AC-05** (US-03) — happy path
**Given** у картці є принаймні один кадр
**When** `user` натискає «Generate all»
**Then** система розпізнає товар із головного кадру, а опис під Prom, ключові слова й опис під OLX приходять і показуються праворуч для правки

**AC-11** (US-05) — domain invariant
**Given** `user` виправив опис під OLX вручну
**When** приходить нова пропозиція на це поле
**Then** вона показана **поруч** зі значенням, а не замість нього — `user` вирішує сам, натискаючи «<- AI»

**AC-21** (US-10) — happy path
**Given** `user` написав текст у полі сам
**When** `user` натискає «? -> AI» для цього поля
**Then** система готує новий варіант саме цього поля з чернетки, не чіпаючи інші поля й без фото

**AC-22** (US-10) — error
**Given** поле порожнє
**When** `user` дивиться на кнопку «? -> AI» цього поля
**Then** кнопка недоступна

## Checklist

1. `products-api.ts` — методи запуску (з `scope`, і для `field` — `field`/`draftText`), стану, прийняття й відхилення.
2. Парні поля в наявній підфічі `products/form/`: ліворуч поточне значення, праворуч остання пропозиція, для кожного з `titleProm`, `titleOlx`, `descriptionProm`, `descriptionOlx`, `seoKeywords`.
3. Кнопка «Generate all» нагорі (`scope: texts`); кнопки «? -> AI» (`scope: field`, disabled на порожньому полі, AC-22) і «<- AI» (`acceptFieldSuggestion`) — на кожному парному полі.
4. Полінг стану із зупинкою на `succeeded` і `failed` **і при виході з екрана** — спільний для запуску «Generate all» і для кожного «? -> AI».
5. Непідтверджені пропозиції поруч із полями.
6. AC-10b: коли тексти є, а ціни немає — показати це й дати запросити саму лише ціну (`scope: price`, окремо від парних полів).
7. AC-14: вартість картки в токенах.
8. Вичерпаний ліміт частоти й недоступна модель — текстом українською за полем `code`; ліміт спільний для «Generate all» і «? -> AI» (PRD §6.1).

## Out of scope

- Нова підфіча: парні поля живуть у `products/form/`, окремого каталогу не заводимо, поки екран читається.
- Пакетна підготовка кількох карток — [PRD §3](../PRD.md#3-non-goals), non-goal.
- Блокування полів і кнопок до першого кадру (AC-20) — [T20](add-product-form-subfeature.md).
