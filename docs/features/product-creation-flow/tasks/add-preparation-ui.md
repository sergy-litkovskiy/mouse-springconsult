# T32 — Фронт підготовки: запуск, полінг, пропозиції, вартість

## Context

Екран, на якому обіцянка [PRD §2](../PRD.md#2-goals) стає видимою: тексти під обидва
майданчики й ціна зʼявляються в картці одним запуском, без переходу в зовнішній чат.

Полінг зʼявляється саме тут — і це адитивна зміна, яку
[sad.md §9](../sad.md#9-architecture-decisions) свідомо лишив без ADR: у поставці 1 його не
було, бо фонової роботи не було.

**Уточнення 2026-09-12 (мокап картки, `docs/assets/add-edit-product-feature.pdf`).** Замість
окремої «панелі підготовки» з вибором області — парне поле на кожен текстовий рядок
(заголовок Prom/OLX, опис Prom/OLX, ключові слова): ліворуч поточне значення (ручний ввід
або застосована пропозиція), праворуч — остання пропозиція моделі, і дві кнопки:

- **«Generate all»** (одна кнопка нагорі, над галереєю) — запускає `scope: texts`,
  розпізнає товар із головного кадру й заповнює праворуч усі поля одразу ([ADR 0014](../adr/0014-let-ai-recognize-the-item-from-photos.md)).
- **«? -> AI»** (біля кожного поля) — запускає `scope: field` для цього поля з поточної
  чернетки ліворуч, без фото (US-10, [ADR 0015](../adr/0015-add-per-field-text-rewrite-scope.md)); недоступна, доки поле порожнє (AC-22).
- **«<- AI»** (біля кожного поля) — приймає останню пропозицію цього поля
  (`acceptFieldSuggestion`, [T30](add-suggestion-resolution-endpoints.md)) і копіює її
  значення в поле ліворуч. На щойно створеній картці перша пропозиція для поля вже
  застосована сама (ADR 0006) — кнопка стає потрібною саме в момент розходження (AC-11).

Ціна лишається окремою дією поза цим паттерном — `scope: price` не читає чернетку, кличе
`web_search`.

**Уточнення 2026-09-13 (кнопка ціни, PRD AC-23–AC-27).** Поле ціни отримує той самий
візуальний паттерн (ліворуч поточне значення, праворуч результат), але з двома відмінностями.
Перша: кнопка одна — «? -> AI» між лівим і правим полем, без «<- AI». Клік запускає
`scope: price` незалежно від того, чи натискалося «Generate all» раніше й чи є вже прийнята
ціна (AC-23); кнопка недоступна, доки в картці немає жодного заголовка — ні `titleProm`, ні
`titleOlx` (AC-24, той самий паттерн disabled-стану, що й AC-22). Сам опис без заголовка
кнопку не вмикає — фронт перевіряє ту саму умову, яку сервер гейтить кодом
`preparation_input_incomplete`, `details.missing: ["title"]` (AC-27, [T29](add-preparation-run-endpoints.md)),
але робить це раніше, без зайвого запиту. Друга: праворуч зʼявляється діапазон
«від — до» (`{priceFrom, priceTo}`) як **звичайний текст, не елемент керування** — на відміну
від текстових полів, тут немає ні кліку, ні автозаповнення. `user` дивиться на діапазон і сам
вписує обране число (чи власний рахунок) у поле ціни ліворуч руками, тим самим шляхом, що й
будь-яке ручне введення ціни (AC-25). `acceptFieldSuggestion` для `field: price` фронт не
викликає ніколи: бекенд відмовляє йому кодом `price_suggestion_readonly` (AC-26,
[T30](add-suggestion-resolution-endpoints.md)). Саме збереження числа в `products.price`
відбувається пізніше, тим самим `PATCH`, що й ручне редагування ціни.

## Sequence

[sad.md §6](../sad.md#6-runtime-view), **сценарій 7** — цикл опитування, **сценарій 8** —
запит ціни й вибір значення з діапазону, **сценарій 10** — регенерація й прийняття одного
поля, і **сценарій 5** — часткова відмова, яку фронт має показати:

> `web->>api: перечитує картку`
> `api-->>web: тексти є пропозиціями, ціни немає`
> `user->>web: запитує саму лише ціну, не перезапускаючи тексти`

## Data delta

**Немає.** Але одна властивість схеми визначає поведінку таймера: `created_at` запуску є
входом обмеження частоти ([data-model.md](../data-model.md)), тож полінг, який не зупинився
після виходу з екрана, зʼїдає ліміт і коштує грошей.

## Acceptance criteria

**AC-05** (US-03) — happy path
**Given** у картці є принаймні один кадр
**When** `user` натискає «Generate all»
**Then** система розпізнає товар із головного кадру, а опис під Prom, ключові слова й опис під OLX приходять і показуються праворуч для правки

**AC-11** (US-05) — domain invariant
**Given** `user` виправив опис під OLX вручну
**When** приходить нова пропозиція на це поле
**Then** вона показана **поруч** зі значенням, а не замість нього — `user` вирішує сам, натискаючи «<- AI»

**AC-21** (US-10) — happy path
**Given** `user` написав текст у полі сам
**When** `user` натискає «? -> AI» для цього поля
**Then** система готує новий варіант саме цього поля з чернетки, не чіпаючи інші поля й без фото

**AC-22** (US-10) — error
**Given** поле порожнє
**When** `user` дивиться на кнопку «? -> AI» цього поля
**Then** кнопка недоступна

**AC-23** (US-04) — happy path
**Given** картка має принаймні один текст
**When** `user` натискає «? -> AI» біля ціни — незалежно від того, чи запускалося «Generate all»
**Then** система запускає пошук ціни (`scope: price`) і показує діапазон «від — до» праворуч; ліве поле ціни не змінюється сама собою

**AC-24** (US-04) — error
**Given** картка не має жодного заголовка — ні `titleProm`, ні `titleOlx`
**When** `user` дивиться на кнопку «? -> AI» біля ціни
**Then** кнопка недоступна; наявність самого лише опису без заголовка кнопку не вмикає

**AC-25** (US-04) — domain invariant
**Given** праворуч показаний діапазон ціни
**When** `user` вирішує, яку ціну зберегти
**Then** `user` сам вписує число в поле ціни ліворуч руками, тим самим шляхом, що й будь-яке ручне введення; система нічого не копіює й не підставляє — праворуч лишається текст, не елемент керування

## Checklist

1. `products-api.ts` — методи запуску (з `scope`, і для `field` — `field`/`draftText`), стану, прийняття й відхилення.
2. Парні поля в наявній підфічі `products/form/`: ліворуч поточне значення, праворуч остання пропозиція, для кожного з `titleProm`, `titleOlx`, `descriptionProm`, `descriptionOlx`, `seoKeywords`.
3. Кнопка «Generate all» нагорі (`scope: texts`); кнопки «? -> AI» (`scope: field`, disabled на порожньому полі, AC-22) і «<- AI» (`acceptFieldSuggestion`) — на кожному текстовому парному полі.
4. Поле ціни — той самий парний вигляд, але з **однією** кнопкою «? -> AI» (`scope: price`, disabled без жодного заголовка — `titleProm`/`titleOlx`, AC-24) і без «<- AI»: праворуч — звичайний текст діапазону, не елемент керування; `user` сам руками вписує число в ліве поле (AC-23, AC-25) — `acceptFieldSuggestion` для `field: price` не викликається.
5. Полінг стану із зупинкою на `succeeded` і `failed` **і при виході з екрана** — спільний для запуску «Generate all», кожного «? -> AI» текстового поля і кнопки ціни.
6. Непідтверджені пропозиції поруч із полями.
7. AC-10b: коли тексти є, а ціни немає — той самий елемент керування ціною (кнопка «? -> AI» вже видима й доступна) дозволяє запросити саму лише ціну — окремого UI для цього випадку більше не потрібно.
8. AC-14: вартість картки в токенах.
9. Вичерпаний ліміт частоти й недоступна модель — текстом українською за полем `code`; ліміт спільний для «Generate all», «? -> AI» текстових полів і кнопки ціни (PRD §6.1).

## Out of scope

- Нова підфіча: парні поля живуть у `products/form/`, окремого каталогу не заводимо, поки екран читається.
- Пакетна підготовка кількох карток — [PRD §3](../PRD.md#3-non-goals), non-goal.
- Блокування полів і кнопок до першого кадру (AC-20) — [T20](add-product-form-subfeature.md).
