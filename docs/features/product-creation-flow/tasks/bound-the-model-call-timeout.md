# T54 — Обмежити таймаут виклику моделі під термін задачі

## Context

Знайдено 2026-09-20 живим прогоном фронту [T32](add-preparation-ui.md) на реальному ключі.
Запуск `scope: price` з `web_search` не вклався у відведені йому п'ять хвилин, і pg-boss
запустив **другу спробу поверх першої, яка ще працювала**:

```
17:16:32  job started  scope: price                  ← спроба 1
17:21:49  job started  scope: price  retry_count: 1  ← спроба 2, перша ще жива
```

Причина — два таймери, які ніхто не узгодив:

- `config.queue.preparation.expireInSeconds` — 5 хв. Після них pg-boss вважає спробу мертвою
  й віддає задачу наступній.
- клієнт створюється як `new Anthropic({ apiKey })` — **без явного таймауту**. Дефолт SDK
  більший за п'ять хвилин, та ще й сам ретраїть усередині себе.

Отже перша спроба не мертва, а лише повільна: вона й далі тримає відкритий виклик, за який
уже заплачено, і паралельно починається другий. `retryLimit: 2` означає до трьох таких
викликів на один запуск. Це той самий клас дефекту, що й [T51](allow-retry-after-failed-run.md)
і [T52](close-stuck-preparation-runs.md) — ціна помилки вимірюється в грошах, а не в незручності.

Обхід із T52 тут не рятує: він закриває запуск через ~22 хв, коли всі три виклики вже
оплачені.

## Data delta

**Немає.** Задача змінює лише `config.ts` і створення клієнта.

## Acceptance criteria

**AC-A** — domain invariant
**Given** виклик моделі триває довше, ніж відведено спробі
**When** pg-boss доходить до межі `expireInSeconds`
**Then** виклик уже обірваний власним таймаутом клієнта — друга спроба ніколи не йде поверх
живого виклику

**AC-B** — domain invariant
**Given** запуск `scope: price` з `web_search`, найповільніший з усіх
**When** його спроба вкладається у власний таймаут
**Then** вона не обривається передчасно: межа клієнта взята з реального часу такого виклику,
а не зі здогаду

**AC-C** — error
**Given** виклик обірвано таймаутом клієнта
**When** обробник це бачить
**Then** спроба завершується помилкою, яку `worker` уже вміє обробляти — шлях `abandon` з
[T52](close-stuck-preparation-runs.md) лишається чинним

## Checklist

1. `config.ts` — явна константа таймауту виклику моделі, виведена з `expireInSeconds` так, щоб
   клієнт завжди здавався **першим**; поруч коментар з причиною (два таймери, подвійна оплата).
2. `AnthropicAdapter` — `new Anthropic({ apiKey, timeout, maxRetries })`: обидва явні, бо
   дефолт SDK непомітно зсуває межу при оновленні залежності. Внутрішні ретраї SDK теж
   входять у бюджет спроби, тож їх треба або вимкнути, або врахувати у формулі.
3. Виміряти, скільки насправді триває `scope: price` з `web_search` на реальному ключі, і
   назвати це число в коментарі: без нього AC-B перевірити нічим.
4. Перевірити, чи `expireInSeconds: 5 * 60` узгоджується з цим виміром — можливо, збільшити
   треба саме його, а не зменшувати таймаут клієнта.
