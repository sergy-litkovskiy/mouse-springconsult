# T43 — Перегляд фото товару з каталогу

## Context

Запит 2026-09-17, UI-доопрацювання до поставки 2. Сьогодні лічильник кадрів у колонці
«Фото» відкриває форму картки (`openForm(product)` у `product-catalog.ts`). Підставу
записано в коментарі: галерея стоїть угорі діалогу картки (макет 2026-09-12). Мініатюра
власного обробника не має, тож клік по ній спливає до рядка й теж відкриває форму.

Нова вимога **змінює рішення [T22](integrate-catalog-with-form-and-delete.md)**. Клік по
мініатюрі або по лічильнику відкриває легкий переглядач (міні-слайдер) лише для перегляду
всіх фото. Редагування в ньому немає. Клік по решті рядка, як і раніше, відкриває форму.

**Дані вже є.** Кожен рядок `ProductList.items` несе `images` з повною `url`, `position` і
`isMain`. Переглядачу не потрібен ні новий запит до `api`, ні правка контракту. Кадри
браузер бере з R2 напряму ([ADR 0007](../adr/0007-serve-images-from-a-public-bucket.md)).

**Де лежить.** Новий компонент `image-viewer.ts` (+ `.html`, `.css`) у наявній підфічі
`products/gallery/`: він теж про кадри картки, тож нового каталогу не треба (правило 15
`apps/web/CLAUDE.md`). Відкривається через `MatDialog`, так само як форма.

**Поведінка слайдера.** Великий кадр, кнопки «Попереднє» / «Наступне», клавіші ← →,
лічильник «2 / 5» і смуга мініатюр для переходу. Перегляд починається з головного кадру,
а далі кадри йдуть за `position`. Esc і кнопка «Закрити» закривають діалог.
Оригінали повнорозмірні, тож завантажувати слід лише показаний кадр і мініатюри
(`loading="lazy"`), а не всі оригінали одразу.

## Sequence

Власного сценарію немає: дані вже приїхали зі списком. [sad.md §6](../sad.md#6-runtime-view)
описує таке саме для маркування:

> «`isReady` уже їде в кожному рядку `ProductList.items` (`contracts/openapi.yaml`) — новий запит бекенду не потрібен»

## Data delta

**Немає.** Ні схема, ні контракт не змінюються.

## API contract excerpt

```yaml
        images:
          type: array
          maxItems: 10
          items: { $ref: "#/components/schemas/ProductImage" }
    ProductImage:
      required: [id, r2Key, url, position, isMain]
        position: { type: integer, minimum: 0 }
        isMain: { type: boolean }
```

## Acceptance criteria

**AC-40 (нове) — happy path**
**Given** у каталозі картка з трьома кадрами, другий з яких головний
**When** `user` клікає мініатюру або лічильник «3» у колонці «Фото»
**Then** відкривається переглядач із головним кадром і лічильником «1 / 3», форма картки не відкривається, а «Наступне» і клавіша → переходять до наступного кадру за `position`

**AC-40 — edge case**
**Given** переглядач показує останній кадр
**When** `user` натискає «Наступне» або →
**Then** перегляд не виходить за межі: кнопка вимкнена, а кадр не змінюється

**AC-41 (нове) — edge case**
**Given** картка без жодного кадру
**When** `user` клікає заглушку мініатюри або рядок
**Then** переглядач не відкривається: лічильник вимкнений, як і раніше, а клік по рядку відкриває форму картки

## Checklist

1. `products/gallery/image-viewer.ts` / `.html` / `.css`: діалог із `MAT_DIALOG_DATA` (`images`, заголовок картки), індекс сигналом, кнопки й клавіші ← →, лічильник, смуга мініатюр.
2. `image-viewer.spec.ts`: старт з головного кадру, порядок за `position`, межі на першому й останньому кадрі, перехід клавішами.
3. `product-catalog.ts` / `.html`: метод `openViewer(product)`. Лічильник і мініатюра (кнопка з `aria-label`) викликають його з `$event.stopPropagation()`. Коментар над `openForm` оновити: лічильник уже не відкриває форму.
4. `product-catalog.spec.ts`: клік по лічильнику й по мініатюрі відкриває `ImageViewer`, а не `ProductForm`; клік по рядку, як і раніше, відкриває форму. Наявний тест, який перевіряв відкриття форми лічильником, переписати як частину RED.
5. `pw`: картка з кількома кадрами. Перевірити мініатюру, лічильник, стрілки, Esc і ширину 360 px без горизонтального скролу.
6. `PRD.md §5`: AC-40 і AC-41 з посиланням на цю story; у `sad.md §6` дописати речення про переглядач поруч із «Маркування в таблиці каталогу».
