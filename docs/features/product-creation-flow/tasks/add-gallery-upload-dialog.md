# T21 — Секція галереї: локальне превʼю, вивантаження, головний, видалення

## Context

`product-gallery-dialog.ts` існує заготовкою — сьогодні це read-only `MatDialog`
(«Закрито», без дій). **Уточнення 2026-09-12 (мокап картки):** секція галереї
перестає бути окремим `MatDialog`, який відкривають кнопкою; вона стає вбудованим
компонентом нагорі `product-form` ([T20](add-product-form-subfeature.md)) і рендериться
одразу, щойно відкрито картку — `MatDialogModule`/`MAT_DIALOG_DATA` з компонента прибираються,
дані (галерея, `productId`) приходять `@Input()`, як у будь-якого дочірнього компонента
підфічі. Файл лишається в `products/gallery/` (правило 15 — підфіча вільно імпортує сусідню
всередині своєї фічі).

Тут виконується **QG-2**, і виконує його не швидкість сервера: браузер малює обраний файл
локально ще до відповіді ([sad.md §10](../sad.md#10-quality-requirements)). Форма при цьому
лишається придатною до редагування.

Друга половина QG-2 — відмова **до** вивантаження: межа розміру й перелік типів лежать
константами контракту саме для того, щоб браузер не слав десять мегабайтів, які сервер
однаково відхилить.

**Уточнення 2026-09-17 (T20, T38).** Елемент секції в шаблон `product-form` вставляє ця
задача. Нова картка ще не має `id`: перед першим вивантаженням секція просить його в
`ProductForm.ensureProduct()` (порожня картка, T38), а після кожної зміни кадрів передає
галерею в `ProductForm.imagesChanged()`, щоб форма зняла AC-20.

## Sequence

[sad.md §6](../sad.md#6-runtime-view), **сценарій 1**, другий рядок — і він же вся суть QG-2:

> `web->>web: малює превʼю з локального файлу, не чекаючи на сервер`

та **сценарій 4** — гілка видалення з підтвердженням.

## Data delta

**Немає.** Але одна властивість схеми видима саме тут: `product_images_position_key` —
`(product_id, position)` UNIQUE **DEFERRABLE** ([data-model.md](../data-model.md)), тож
позиції після видалення лишаються з діркою. Діалог має показувати порядок, а не номери.

## API contract excerpt

```yaml
    post:
      operationId: uploadProductImage
      responses:
        "409":
              example:
                error: { code: gallery_full, message: "Галерея вміщає щонайбільше десять кадрів" }
        "413":
              example:
                error: { code: file_too_large, message: "Файл перевищує 10 МБ" }
        "422":
              example:
                error: { code: invalid_file, message: "Файл не є зображенням" }
```

Усі три коди фронт має вміти показати українською — текст формує він, не API.

## Acceptance criteria

**AC-01** (US-01) — happy path
**Given** `user` створює нову картку товару
**When** `user` завантажує кадр
**Then** система показує превʼю і не змушує чекати на завершення обробки

**AC-02** (US-01) — domain invariant
**Given** у галереї картки вже десять кадрів
**When** `user` намагається додати ще один
**Then** додавання недоступне, і причина названа

## Checklist

1. Вибір файлів і локальне превʼю з `File` **до** відповіді сервера.
2. Відмова до вивантаження за `maxImageBytes` і `allowedImageTypes` з `products-limits.ts`.
3. Лічильник «N з 10», блокування додавання на десятому.
4. Призначення головного кадру (AC-03); перший кадр приходить із `isMain: true` вже з відповіді сервера (AC-19, [T14](add-image-upload-endpoint.md)) — секція лише показує це, а не встановлює сама.
5. Видалення кадру через `confirm-dialog`.
6. Помилки сервера — за полем `code` через `api-error-message.ts`.

## Out of scope

- Перестановка кадрів — у контракті поставки 1 її немає.
- Індикатор фонової обробки — фонової роботи немає ([ADR 0011](../adr/0011-store-only-the-original-frame.md)).
- Стан «є хоча б один кадр» і вимикання решти полів форми — рахує й тримає [T20](add-product-form-subfeature.md) (AC-20); секція лише повідомляє кількість кадрів нагору.

Результат 2026-09-17:
- `product-gallery-dialog.*` перейменовано на `product-gallery.*` (`ProductGallery`), бо файл називається за тим, що експортує, а діалогом компонент більше не є.
- Лічильник кадрів у каталозі тепер відкриває картку, на верху якої стоїть секція. Інші входи в картку (кнопка створення, клік по рядку) і перечитування списку після закриття лишаються за [T22](integrate-catalog-with-form-and-delete.md).
- `pw` на дроселі (затримка 2 с, вивантаження 5 КБ/с): превʼю через 20 мс, відповідь сервера через 2286 мс. Також перевірено призначення головного кадру, відмову для `.txt` без запиту, «Скасувати» в підтвердженні без запиту і видалення до нуля кадрів: поля й «Зберегти» вимикаються, підказка з'являється, а наступне вивантаження знову їх вмикає.
- Material 3 обмежує діалог 560 px, тож картка відкривається з `maxWidth: '92vw'`.
