# T39 — Відкрита картка називає, чого бракує до готовності

## Context

Дефект з [приймання поставки 1](../_audit/delivery-1-acceptance-2026-09-17.md) (T23, AC-15).
Каталог над бейджем «Неготово» показує підказку «Бракує: опис Prom, ціна…» ([T22](integrate-catalog-with-form-and-delete.md)).
Бейдж у відкритій картці (`product-form`) показує лише «Неготово», і з'ясувати, чого бракує,
там неможливо. На прогоні елементів з текстом «Бракує» у діалозі було 0.

Розбіжність з архітектурою, а не з уподобанням: [sad.md §6](../sad.md#6-runtime-view), абзац
«Маркування в таблиці каталогу», прямо каже, що маркування так само малюється у відкритій
картці, і AC-15 покриває обидва місця одним предикатом.

## Sequence

Власного сценарію немає: перелік рахується на фронті з полів, які вже приїхали в `Product`.
Той самий принцип [sad.md §6](../sad.md#6-runtime-view):

> «Перелік прогалин рахується **на фронті** з полів, які й так приїхали в `Product` … а не окремим полем відповіді»

## Data delta

**Немає.** Ні схема, ні контракт не змінюються.

## API contract excerpt

Джерело переліку — поля `Product`, які форма вже отримує у відповіді `PATCH` і `GET`:

```yaml
    Product:
      properties:
        titleProm: { type: string, maxLength: 200 }
        descriptionProm: { type: string, description: "HTML з переліку ADR 0016" }
        titleOlx: { type: string, maxLength: 200 }
        descriptionOlx: { type: string }
        isReady:
          type: boolean
          description: >-
            Похідне поле, не колонка: обидва заголовки й обидва описи непорожні, price > 0,
            є хоча б один кадр ([ADR 0009](../adr/0009-derive-card-readiness-instead-of-storing-it.md)).
```

## Acceptance criteria

**AC-15** (US-01…US-08, [PRD §5](../PRD.md#5-acceptance-criteria)) — domain invariant
**Given** відкрита картка, якій бракує опису OLX і ціни
**When** `user` наводить курсор на бейдж «Неготово» у заголовку форми
**Then** підказка називає «Бракує: опис OLX, ціна» — тими самими словами й у тому самому порядку, що й каталог

**AC-15** — domain invariant
**Given** відкрита картка стала готовою після збереження
**When** форма отримала відповідь `PATCH` з `isReady: true`
**Then** бейдж показує «Готово», а підказки немає; перелік рахується з останньої відповіді сервера, а не з незбережених полів форми

## Checklist

1. Винести рахування переліку з `product-catalog.ts` (`missingFields`) у функцію поруч, у `apps/web/src/app/products/` — щоб каталог і форма не розійшлися у словах. Нового каталогу не заводити.
2. `product-form.ts` / `product-form.html`: `matTooltip` над бейджем `readiness` з переліком, порахованим з останньої відповіді сервера (там, де вже ставиться `ready`).
3. `product-form.spec.ts`: тест на текст підказки для неготової картки й на її відсутність для готової; наявні тести каталогу лишаються зеленими.
4. `pw`: відкрити неготову картку, навести на бейдж, прочитати підказку.

## Out of scope

- Показ переліку текстом замість підказки — підказка тримає форму однаковою з каталогом.
- Перерахунок «на льоту» з незбережених полів: готовність у формі показує збережений стан.

Примітка 2026-09-17: другу GWT (бейдж «Готово» у формі після збереження) зняла [T45](close-product-form-on-save.md), бо після збереження діалог закривається, а готовність показує каталог.
