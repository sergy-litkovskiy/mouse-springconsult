# T79 — Каталог: скролиться лише вміст таблиці

## Context

Запит 2026-09-30, пункт 2. Зараз скролиться вся сторінка: на 1280×720 при 20 рядках вона має висоту
3412 px, і фільтри, шапка таблиці й обидва пагінатори ховаються після першого ж скролу; нижній
пагінатор стоїть на `top` 3332 px, тобто за п'ять екранів. Власник просить лишити на екрані постійно
фільтри, шапку й підвал таблиці, а скролити тільки вміст; підвал із пагінатором має бути
приліплений до нижнього краю екрана. Верхній пагінатор ([T57](add-top-catalog-paginator.md)) тоді
зайвий, і його прибираємо.

**Форма рішення.** Сторінка стає колонкою висотою в екран, а не документом, що росте:

- `app-layout`: колонка `height: 100dvh` (не `100vh`: на телефоні `vh` не враховує панель браузера);
  `mat-toolbar` — без зайвого росту, `router-outlet` займає решту (`flex: 1; min-height: 0`).
- `.catalog` — колонка на всю решту: шапка й фільтри `flex: none`, картка таблиці `flex: 1; min-height: 0`.
- Усередині картки: `.catalog__scroll` `flex: 1; overflow: auto` — єдине місце, що скролиться; рядок заголовків
  `sticky` (`*matHeaderRowDef="columns; sticky: true"`); нижній `mat-paginator` — останній нащадок колонки, тож
  тримається нижнього краю екрана без `position: fixed`, навіть коли рядків мало чи немає взагалі.
- **Висоту тулбара в CSS не вписуємо** (`calc(100vh - 64px)` заборонено): [T80](shrink-app-bar-catalog-header-and-filters.md)
  її змінить, а flex-колонка підлаштується сама.

**Вузький і низький екран.** На 360 px фільтри займають ~570 px, тож прикріплені вони не лишили б місця
для таблиці. **Припущення:** нижче 600 px завширшки (і на екрані нижчому за 480 px) фільтри й шапка
прокручуються разом зі сторінкою, а прикріпленим лишається лише пагінатор; вище — усе прикріплено, як
просив власник. Межі — у CSS одним `@media`; якщо власник хоче інакше, міняється тільки він.
Пастка: `.catalog__table` має `overflow: hidden` (заокруглення); він не дає `position: sticky` прилипнути до
вікна, тож на вузькому екрані його доведеться зняти.

## Sequence

Власного сценарію немає: це верстка сторінки, запити не змінюються. Так само
[sad.md §6](../sad.md#6-runtime-view) описує стан форми:

> «власного сценарію це не має, бо це стан форми на фронті, а не запит до `api`»

## Data delta

**Немає.** Правка торкається `app-layout.*`, `product-catalog.*` і тесту каталогу.

## API contract excerpt

Пагінація лишається тією самою — `page` і `pageSize` у `listProducts`; зникає лише другий пагінатор:

```yaml
      operationId: listProducts
        - { $ref: "#/components/parameters/Page" }
        - { $ref: "#/components/parameters/PageSize" }
```

## Acceptance criteria

Нове AC-74 із запиту 2026-09-30 і переписане [AC-51](../PRD.md#5-acceptance-criteria) (верхнього
пагінатора більше немає); до PRD §5 їх вносить крок 6 чекліста.

**AC-74 (нове) — happy path**
**Given** `user` відкриває `/products` на екрані 1280×720 з 20 рядками
**When** гортає вміст таблиці вниз
**Then** тулбар, шапка, фільтри, рядок заголовків і пагінатор лишаються на місці (`top` до й після скролу однаковий), нижній край пагінатора збігається з нижнім краєм вікна (±1 px), сама сторінка не скролиться (`scrollHeight <= innerHeight`), а `scrollTop` вмісту таблиці змінюється

**AC-74 — edge case**
**Given** та сама сторінка, у каталозі три рядки, потім жодного, потім висоту вікна змінено до 500 px
**When** каталог відмальований
**Then** пагінатор усе одно стоїть біля нижнього краю вікна, область таблиці займає решту висоти й не має від'ємної висоти

**AC-74 — edge case (вузький екран)**
**Given** `user` відкриває `/products` на екрані 360×740
**When** гортає сторінку
**Then** пагінатор лишається біля нижнього краю вікна, фільтри й шапка прокручуються разом зі сторінкою, горизонтального скролу сторінки немає (`scrollWidth <= clientWidth`)

**AC-51 (переписане) — happy path**
**Given** у каталозі карток більше, ніж на одній сторінці
**When** `user` відкриває `/products`
**Then** є один пагінатор — під таблицею, — і він показує сторінку, розмір і загальну кількість; верхнього пагінатора немає

**AC-51 (переписане) — edge case**
**Given** `user` перейшов на другу сторінку або змінив розмір сторінки в пагінаторі
**When** таблиця перезавантажилась
**Then** URL містить нову сторінку, а перезавантаження сторінки браузера відкриває той самий стан

## Checklist

1. `product-catalog.spec.ts` (RED): один `mat-paginator` без `aria-label` «Верхній пагінатор каталогу»; рядок заголовків має клас `mat-mdc-table-sticky`; тести стану пагінації з URL (наявні) читають єдиний пагінатор. Перейменувати наявні тести, що звертались до верхнього.
2. `product-catalog.html`: прибрати верхній `mat-paginator`, `sticky: true` у `matHeaderRowDef`; `product-catalog.css`: прибрати `.catalog__top-paginator`, зробити `.catalog`, картку й `.catalog__scroll` flex-колонкою з єдиним скролом.
3. `app-layout.css`: колонка `100dvh`, outlet займає решту; висоту тулбара не вписувати.
4. `product-catalog.css`: `@media` для вузького й низького екрана — фільтри й шапка в потоці сторінки, пагінатор прикріплений (зняти `overflow: hidden` з картки, якщо він заважає).
5. `pw`: 1280×720, 1024×600 і 360×740 — скрол вмісту, три рядки, нуль рядків, зміна висоти вікна; `getBoundingClientRect()` тулбара, фільтрів, заголовків і пагінатора до й після скролу; знімки зберегти.
6. `PRD.md §5`: AC-74 і переписане AC-51 з посиланням на цю story; у [T57](add-top-catalog-paginator.md) одним рядком вказати, що верхній пагінатор прибрано.
