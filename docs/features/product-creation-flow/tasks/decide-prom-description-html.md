# T46 — Рішення: опис для Prom зберігається як HTML

> **Гейт третьої хвилі UI-доопрацювання.** T47–T49 не починаються, поки цей файл не
> закритий: вони реалізують рішення, яке суперечить двом чинним правилам.

## Context

Запит 2026-09-18: поле «Опис для Prom» отримує міні-редактор HTML з режимом перегляду й
редагування сирого HTML, а поруч — кнопку «Почистити html». Prom приймає опис у HTML, а
CSV-імпорт (`db/prom-csv.ts`, `cleanDescription`) уже пише в `descriptionProm` очищений HTML.
Тобто HTML у колонці вже є, а правила досі кажуть, що його там немає.

**Що суперечить запиту.**

- Кореневий `CLAUDE.md`, «Чого НЕ робимо»: «Не додаємо WYSIWYG-редактор. Тексти редагуються в `textarea` як plain text».
- `apps/api/src/modules/ai/CLAUDE.md`: відповідь моделі зберігаємо як plain text.

**Рішення власника 2026-09-18.** Опис для Prom є HTML. Відповідь моделі **лишається** plain
text: після прийняття пропозиції `user` доредаговує її в редакторі. Опис для OLX лишається
plain text. HTML чистять і браузер (кнопка, T49), і `api` під час збереження (T47), бо
чистка лише в браузері не захищає від прямого запиту.

Рішення зачіпає контракт, два застосунки й правило в кореневому `CLAUDE.md`, і має живу
альтернативу (plain text з конвертацією в HTML під час вивантаження на Prom). Тому воно
проходить гейт blast-radius, і на нього заводиться ADR 0016.

## Sequence

[sad.md §6](../sad.md#6-runtime-view), ручний шлях. Змінюється зміст кроку: опис для Prom
тепер HTML, а `api` чистить його перед записом.

> `user->>web: вписує обидва заголовки, описи, ключові слова й ціну`
> `api->>pg: одним оновленням пише заголовки, тексти, слова й ціну`

## Data delta

Схема не змінюється: `description_prom` лишається `text`. Змінюється **зміст**: рядок
тепер HTML. Рішення №5 нижче вирішує, чи конвертувати наявні plain-text рядки.

## API contract excerpt

```yaml
      operationId: updateProduct
    ProductUpdateRequest:
        descriptionProm: { type: string, maxLength: 8000 }
```

## Acceptance criteria

**AC-45 (нове) — рішення записане**
**Given** ADR 0016 прийнято
**When** виконавець T47–T49 читає кореневий `CLAUDE.md`, `ai/CLAUDE.md` і PRD
**Then** жоден із цих документів не забороняє HTML в описі для Prom і не вимагає його

**AC-45 — edge case**
**Given** модель повернула опис для Prom як plain text з абзацами через `\n\n`
**When** `user` приймає пропозицію й відкриває картку в редакторі
**Then** абзаци видно як абзаци, а не як один рядок; де саме plain text стає `<p>`, записано в ADR

## Checklist

1. **ADR 0016** `adr/0016-store-the-prom-description-as-html.md`: контекст, рішення, відкинута альтернатива (plain text + конвертація під час вивантаження), наслідки.
2. **Перелік дозволених тегів і атрибутів.** Узяти за основу `allowedTags` з `cleanDescription` і записати його в ADR. Константа ляже в `apps/api/src/contracts/prom-description-html.ts` без залежностей, щоб фронт імпортував її в рантаймі (конвенція «Контракти»). Створює її T47.
3. **Бібліотека редактора.** Сумісність з Angular 22 і zoneless, режим сирого HTML, розмір бандла. Звіряти з офіційною документацією, а не з пам'яті. Записати вибір і назву npm-пакета в ADR.
4. **Чистка в браузері.** Готова бібліотека (DOMPurify) чи обхід `DOMParser` з тим самим переліком. Обидві чистки мають давати той самий результат на спільному наборі прикладів. Цей набір стає тестами T47 і T49.
5. **Наявні plain-text рядки.** Картки, введені вручну до T48, мають опис без тегів. Редактор склеїть їх абзаци. Варіанти: міграція даних (обгорнути в `<p>`) або конвертація під час завантаження у форму. Вирішити й записати.
6. **Ліміт 8000 символів** тепер рахує й розмітку. Лишити чи підняти, записати в ADR.
7. **Прийняття пропозиції моделі** (T30): записати в Checklist T30, де plain text стає `<p>` (рішення AC-45, edge case).
8. **Готовність картки.** Порожній редактор дає `<p></p>`. Серверна чистка має зводити його до `""`, інакше предикат готовності рахуватиме порожній опис заповненим.
9. **Правила.** Кореневий `CLAUDE.md`: переписати рядок про WYSIWYG (редактор дозволений лише для опису Prom, решта текстів — `textarea`). `ai/CLAUDE.md`: додати, що plain text для `descriptionProm` доходить до HTML за рішенням №7. `PRD.md`: AC-45, а також примітка в `sad.md` §4.

## Out of scope

- Сам редактор, кнопка й серверна чистка — T48, T49, T47.
- HTML для OLX: OLX розмітки не приймає.
