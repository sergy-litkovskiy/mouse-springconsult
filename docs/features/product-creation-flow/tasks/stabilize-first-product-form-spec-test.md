# T89 — Перший тест `product-form.spec.ts` не впирається в таймаут під навантаженням

## Context

Знахідка 2026-10-02 під час T88. Повні прогони `web npm run test` ішли по три паралельно, і на 39 таких прогонів
тест `product-form.spec.ts` › «without a single frame (AC-20)» › «keeps every field and the save button unavailable»
двічі впав з `Error: Test timed out in 5000ms` (5523 і 5694 мс). Обидва падіння припали на першу хвилю, з холодною
збіркою. Наступний тест того ж файлу в цих прогонах пройшов за 811 мс. Зазвичай перший тест триває 1,2–1,9 с, під
навантаженням — до 4,8 с. Послідовно (111 прогонів) він не впав жодного разу.

**Гіпотеза.** Це перший тест файлу, тож він платить за холодний старт: компіляцію `ProductForm` з модулями Material у
TestBed, перший harness і запуск `import()` Tiptap у вкладеному редакторі. 5 с — дефолтний `testTimeout` vitest
(у `angular.json` його не задано), а холодний старт під навантаженням цей бюджет інколи з'їдає. T88 лікувала той
самий клас проблем в іншому місці: там бюджет очікування задавали тики, тут — таймаут тесту.

**Що робимо.** Спершу відтворюємо, як у T88: прогони по три паралельно, доки не впаде двічі, і назва тесту з кожного
падіння. Якщо падає не перший тест файлу або помилка інша, ніж `Test timed out`, гіпотеза хибна, і задача йде в `plan`.
Якщо гіпотеза підтвердилась, холодний старт виносимо з першого тесту: `beforeAll` у `describe('ProductForm')` один раз
створює й знищує форму з власним бюджетом часу (наприклад, 15 с), а тести лишаються на дефолтних 5 с. Глобально таймаут
не піднімаємо: так ховається справжнє зависання будь-якого тесту.

```yaml
        descriptionProm: { type: string, description: "HTML з переліку ADR 0016" }
```

## Acceptance criteria

Нового AC немає: це стабільність тестів без зміни поведінки.

**Критерій — стабільність**
**Given** гілка з правкою
**When** повний `docker compose run --rm --no-deps web npm run test` проганяють 39 разів, по три паралельно, а потім 30 разів поспіль
**Then** усі прогони зелені

**Критерій — тести ті самі**
**Given** та сама гілка
**When** порівнюємо її з `main`
**Then** кількість тестів у підсумку vitest та сама, а diff не додає й не прибирає жодного рядка з `expect`

## Checklist

1. Відтворити до правки: повні прогони `web npm run test` по три паралельно, доки не впаде двічі; записати назву тесту й помилку кожного падіння.
2. `product-form.spec.ts`: холодний старт — у `beforeAll` з власним бюджетом часу; тести лишаються на дефолтному таймауті, `expect` не змінюються.
3. 39 повних прогонів по три паралельно й 30 поспіль зелені; підсумок vitest — та сама кількість тестів, що до правки.
